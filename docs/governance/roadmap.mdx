NTL development follows a phased approach, from specification to production readiness.

## Phase 0: Foundation

**Status:** Complete

- [x] Core concept definition
- [x] Documentation skeleton (Mintlify)
- [x] Protocol specification beta_0.0.0
- [x] Signal format, including delivery class and receipts
- [x] Crypto interface specification
- [x] Learning model — reward signal, update rule, decay, exploration
- [x] Threat model, with an explicit out-of-scope list
- [x] Delivery semantics — best-effort and acknowledged classes
- [x] Storage interface — pluggable, no named database
- [x] Repository structure and CI

**Goal:** A complete, reviewable specification that any team could implement.

## Phase 1: Reference Implementation (Current)

**Status:** In Progress

- [x] Signal encoding/decoding (CBOR)
- [x] Node identity and keypair management, persisted across restarts
- [x] Crypto module: classical (Ed25519)
- [ ] Crypto module: post-quantum (Dilithium + Kyber)
- [x] Pluggable storage: `NodeStore` trait, SQLite backend, conformance suite
- [x] Synapse formation and signed handshake
- [x] Propagation engine with stochastic path selection
- [x] Activation gate — batched firing, bounded queue, latency guard
- [x] Learning loop — receipts, timeout sweep, influence caps, normalisation
- [x] CLI tooling (`ntl init`, `start`, `emit`, `listen`, `synapses`, `status`, `topology`)
- [x] `ntl-node` and `ntl-edge` binaries
- [x] Two-node learning demonstration
- [x] Benchmarks and CI, including a wasm32 build check on `ntl-core`
- [ ] QUIC transport (currently TCP with length-prefixed CBOR)
- [ ] Public test network with bootstrap nodes

**Goal:** A working Rust implementation that can form a network and propagate
signals. Two nodes on one machine already do.

## Phase 2: Adapters and Integration

**Status:** Not Started

- [ ] Web2 adapter (HTTP, WebSocket)
- [ ] Web3 adapter (EVM chains, DID)
- [ ] Legacy API adapter
- [ ] PostgreSQL storage backend
- [ ] Correlation engine for request-response patterns
- [ ] Signal compression (LZ4)
- [ ] Edge node (lightweight) implementation

**Goal:** NTL can connect to real-world systems and persist state.

## Phase 3: Production Hardening

**Status:** Not Started

- [ ] Advanced propagation (Targeted, Gradient scopes)
- [ ] Dynamic threshold tuning
- [ ] Synapse topology optimization
- [ ] Monitoring and observability (OpenTelemetry)
- [ ] Performance benchmarking suite
- [ ] Security audit
- [ ] Formal verification of core protocol properties

**Goal:** NTL is production-ready for real workloads.

## Phase 4: Ecosystem

**Status:** Not Started

- [ ] Client libraries: Go, Python, TypeScript, C
- [ ] Kubernetes operator
- [ ] Docker images and compose files
- [ ] Managed NTL service (The Bundu Foundation)
- [ ] Developer documentation and tutorials
- [ ] Community governance formalization

**Goal:** NTL has a thriving ecosystem and is used in production by multiple organizations.

## Long-term Vision

- Formal IETF standardization process
- Quantum-era crypto module updates as standards evolve
- Integration with AI agent frameworks as native transport
- Global bootstrap network operated by community
- NTL as the default transport for Mukoko and the broader Bundu ecosystem
